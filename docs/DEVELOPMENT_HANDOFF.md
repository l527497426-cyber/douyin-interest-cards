# 抖音兴趣卡专题页｜研发交付说明

> 交付形态：可运行 Coding 产物（无独立 Figma 设计稿）  
> 当前设计与交互唯一基准：本仓库运行结果  
> 页面入口：`/`  
> 本地预览：`http://localhost:3002/`

## 1. 交付原则

本项目采用“代码即设计稿”的交付方式。页面的真实布局、响应式断点、动效时序、图片裁切和交互状态均以当前代码及浏览器渲染结果为准，不应根据截图反推尺寸。

研发接手时请遵循以下优先级：

1. 浏览器中的实际渲染结果；
2. `app/page.tsx` 中的内容结构、数据和交互参数；
3. `app/globals.css` 中的视觉与响应式规则；
4. `public/assets/` 中当前被源码引用的正式资产；
5. 本文档中的模块说明与验收要求。

交付目录只保留当前运行所需资产。历史图片版本已从工作区清理，如需回溯应使用 Git 历史或原始生成记录；正式使用版本始终以 `app/page.tsx` 的引用为准。

## 5. 模块交付说明

### 5.1 全局顶部导航

- 桌面端展示开放平台 Logo、主导航、搜索占位、控制台、登录/注册。
- 首屏区域会根据背景亮度切换导航主题。
- 移动端隐藏不适合窄屏的导航内容，保留核心品牌和入口。
- 当前大部分平台导航使用 `#` 占位，接入真实业务时需要产品提供 URL 映射。
- “开始创作”“控制台”“登录/注册”等核心入口当前统一指向 `CREATE_URL`。

### 5.2 首屏滚动叙事

实现位置：`app/page.tsx` 的 `.edition-hero` / `.hero-sticky`。

核心行为：

- 首屏为高滚动区，画面固定，通过页面滚动驱动 193 帧 WebP 序列。
- 逐帧素材路径规则：`/assets/hero-frames-v4/frame-001.webp` 至 `frame-193.webp`。
- 门户转场使用 CSS mask 与 `PortalTransition` canvas 联合完成。
- 鼠标移动会产生轻量视差和 Liquid 流体反馈。
- CTA 中的主按钮包含独立 Liquid 轨迹效果。
- 首次进入包含短暂的流体揭幕与文字出现动效。
- 用户开启 `prefers-reduced-motion` 或使用粗指针设备时，自动关闭/简化高成本 canvas 与位移动效。

当前关键参数位于 `app/page.tsx` 顶部：

| 参数 | 当前值 | 说明 |
| --- | ---: | --- |
| `HERO_FRAME_COUNT` | 193 | 首屏总帧数 |
| `HERO_VIDEO_END_SCROLL_PROGRESS` | `.82` | 视频序列完成位置 |
| `HERO_PORTAL_START_SCROLL_PROGRESS` | `.794` | 门户开始位置 |
| `HERO_PORTAL_END_SCROLL_PROGRESS` | `.98` | 门户结束位置 |
| `HERO_LIQUID_END_PORTAL_PROGRESS` | `.7` | 首层 Liquid 停止节点 |

视觉验收：

- 刷新时页面不得自行跳到中段；
- 画面滚动应连续，无明显白闪或缺帧；
- 主标题、正文和按钮在背景上保持可读；
- 鼠标反馈不能影响点击 CTA；
- 移动端不应因 Canvas 导致横向溢出。

### 5.3 创作方向模块

数据源：`interestDirections` 与 `interestFeatureImages`。

当前包含 8 个 Tab：网球、电影、游戏、美食、旅行、宠物、阅读、城市漫步。

交互规则：

- 桌面端 8 个 Tab 单行展示，容器宽度约为正文的 70%，左对齐；
- 移动端始终横向滚动，不允许换行顺排；
- 激活项显示蓝色文字和进度提示；
- 自动轮播周期为 `INTEREST_AUTOPLAY_MS = 8000`；
- 点击 Tab 立即切换并重置轮播周期；
- 两侧使用白色渐隐蒙板，让横向内容自然进出；
- Tab 底部无整条灰色基线；
- hover 为浅灰圆角底，不添加下划线，文字保持水平、垂直居中。

内容区由左右两部分组成：

- 左侧 `.feature-stage`：兴趣主视觉、方向标题、说明、创作 CTA、官方激励信息；
- 右侧 `.signal-panel`：真实需求标题、用户原声、创作者原声。

切换动效要求：

- 主图内容与右侧原声面板只做透明度过渡；
- 两者速度保持一致；
- 禁止从下方位移进场；
- 原声卡中的头像和文案作为整体移动与对齐，不拆开做不同节奏。

原声卡视觉规则：

- 外层背景颜色从对应兴趣主图提取，但必须高明度、干净、避免灰脏；
- 顶部为短距离 `90% → 0` 白色渐变，白色层位于内描边下方；
- 底色渐变至少覆盖卡片下方约三分之二区域；
- 单卡描边必须一圈同色，为对应色相的近黑纯色并以约 4% 透明度呈现；
- 描边为内描边；
- 原声卡自身无投影，白色背景保留适度透明；
- 用户/创作者标签与 @名称保持同级视觉强度；
- 头像与整组文案在卡片内略高于绝对几何居中：上方空间略少、下方略多。

### 5.4 创作者案例横向画廊

组件：`HorizontalCases`、`CreatorCaseCard`。

当前 4 个案例：

1. 春日逛展人格；
2. 机械键盘推荐；
3. F1 车手人格；
4. 周末城市漫游地图。

滚动与布局：

- 案例区为纵向滚动驱动的横向轨道；
- 当前轨道位移为 `-progress * 184vw`；
- 卡片左右视觉区域是两个独立容器，不依赖透明叠层拼接；
- 左侧为模糊放大的手机界面背景 + 手机框；
- 右侧为浅色文案区；
- 两侧不使用阴影；
- 外描边保持极弱，避免圆角抗锯齿处出现底图透色或双重描边；
- 整张卡片结构由父级裁切，左右圆角必须在常见 DPR 下保持干净。

背景处理：

- 左侧模糊背景从手机界面图继承；
- 在背景图上叠加与右侧卡片同方向的高饱和提亮色，而非纯白蒙膜；
- 混合模式需让底图继续可见；
- 模糊值应足够高，避免背景细节与手机主图竞争；
- 右侧底色整体偏浅，四张卡片亮度尽量一致。

按钮规则：

- 桌面宽屏展示“创作同类 / 体验案例”；
- `1280px` 以下仅当双按钮确实放不下时改为“创作 / 体验”；
- 单按钮场景不应缩短为无意义文字；
- 按钮始终保留文字，不可只剩图标；
- 按钮箭头统一使用 `/assets/button-arrow-up-right.svg`，视觉尺寸已整体缩小 2px。

当前正式手机界面资产：

| 案例 | 当前文件 |
| --- | --- |
| 春日逛展 | `case-ui-gallery-banner-v7.png` |
| 机械键盘 | `case-ui-keyboard-banner-v5.png` |
| F1 赛车 | `case-ui-f1-banner-v5.png` |
| 城市漫游 | `case-ui-city-banner-v5.png` |

四张手机界面的顶部约束：

- 不显示系统时间、信号、Wi-Fi、电量；
- 不显示“经验 / 同城 / 关注 / 商城 / 推荐”等平台 Tab；
- 不显示顶部搜索；
- 仅保留左上角单一关闭入口；
- 背景图片需要自然补全，不能使用色块遮盖。

春日逛展界面的额外规范：

- UI 以暖白、石墨灰、珊瑚色为主，不能使用大面积蓝色界面；
- “城市灵感策展人”与三个兴趣方向位于同一张完整卡片；
- 不使用标题竖杠或三栏竖向分隔线；
- 三个图标为统一的实体空间符号，不使用细线图标、通用立方体或光圈图标。

### 5.5 创作支持模块

模块包含入门课程、发布指南、社区问答与反馈三张卡。

- 整张卡片均为可点击热区，不应只有底部文字区域可点击；
- 桌面端三列排列；
- 移动端按现有 CSS 适配；
- 卡片数字、标题、描述与装饰形状为整体 hover 状态；
- 当前链接仍为 `#`，上线前需要替换为真实课程、指南和社群地址；
- 如社区入口需要展示二维码，应接入正式二维码资产，当前“QR”为视觉占位。

### 5.6 最终 CTA 与三维兴趣卡

- 背景为 CanvasUI `Blaze` 效果，当前默认值由 `DEFAULT_BLAZE_TUNING` 控制；
- 主文案使用软模糊逐字进入效果；
- 右侧兴趣卡支持鼠标/触控拖拽旋转；
- 拖拽纵向旋转限制在约 `-6°` 至 `6°`，横向随拖动累积；
- 兴趣卡由正反面与 17 层深度层组成；
- `prefers-reduced-motion` 下停用自动旋转和火焰动画；
- 移动端将兴趣卡移到文案下方，避免横向溢出。

### 5.7 页尾

- 页尾结构、友情链接和备案信息目前为展示内容；
- 多数链接仍为 `#`；
- 举报邮箱已使用 `mailto:`；
- 上线前需由业务方确认公司主体、备案号、举报电话和链接有效性。

## 6. 响应式交付标准

主要断点：

| 断点 | 用途 |
| --- | --- |
| `> 1280px` | 案例双按钮完整文案、完整桌面布局 |
| `901–1280px` | 桌面/平板过渡，必要时使用双按钮短文案 |
| `<= 900px` | 移动布局、隐藏桌面 Rail/部分导航、案例和内容重排 |
| `<= 560px` | 手机字号、间距、卡片与按钮进一步收紧 |

移动端必须逐项检查：

- 页面无整体横向滚动条；
- 8 个兴趣 Tab 单行横向滚动，不换行；
- Tab 两侧渐隐不阻止点击或滚动；
- 所有 CTA 至少保留 2 个汉字；
- 文案不得被圆角或手机模型裁切；
- 原声卡最多保持设计所允许的行数，避免单条文本导致卡片高度跳变；
- 横向案例可完整浏览四张；
- 固定/粘性模块退出后不覆盖下一章节；
- Canvas 在低性能设备上使用降级分支。

推荐验收视口：`1440 × 900`、`1280 × 800`、`1024 × 768`、`768 × 1024`、`390 × 844`、`375 × 812`。

## 7. 字体、颜色与形状

- 全站中文使用现代无衬线字体栈：`PingFang SC`、`Noto Sans SC`、系统 sans-serif；
- 不引入宋体/明体作为界面正文或标题；
- 正文主色接近 `#111315`，辅助文字为中性灰；
- 页面基础圆角、内容间距和控制高度由 `app/globals.css` 的根变量及模块变量控制；
- 常规按钮当前控制高度为 `48px`；
- 新增样式应优先复用已有变量，不要在 JSX 中散落重复的尺寸和颜色；
- 案例卡、原声卡默认不增加外投影；需要层次时优先使用底色差、内描边和空间间距。

## 8. 动效与无障碍

- 内容标题使用 `SoftBlurInGroup`，仅在进入视口时播放；
- Tab 和案例切换应保持快速、克制，核心信息不可为了动效而隐藏；
- 所有重要动效均需提供 `prefers-reduced-motion` 降级；
- 装饰图片使用空 `alt`，内容图片提供中文说明；
- 纯图标按钮必须有 `aria-label`；
- Tab 使用 `aria-pressed` 表达选择状态；
- 禁用章节使用 `aria-disabled`；
- 全卡点击时需保留可聚焦元素及可见的键盘焦点样式，不能只绑定父级 `onClick`。

## 9. 性能要求

- 8 张兴趣方向主图已使用 WebP，禁止回退为同尺寸 PNG；
- 首屏逐帧资源较多，应维持按需加载和浏览器缓存，避免一次性阻塞首屏文字；
- 案例手机图虽然为 PNG，但只加载当前页面需要的 4 个正式版本；
- 不在交付目录保留未引用的历史资产版本；
- Canvas 特效应继续保持移动端/低动态偏好的降级逻辑；
- 图片保持明确尺寸和稳定容器比例，避免切换造成 CLS；
- 合并代码前至少执行 `npm run build`。

## 13. 建议的后续工程化

1. 将 `app/page.tsx` 拆分为 Header、Hero、DirectionModule、Cases、Support、FinalCTA、Footer；
2. 将 `interestDirections`、`cases` 和页尾数据迁移到独立内容文件；
